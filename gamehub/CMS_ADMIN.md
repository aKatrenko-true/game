# GameHub CMS — редактор сайта

Страница редактора: `/admin/cms`. Используется тот же пароль, что и для `/admin` (`ADMIN_PASSWORD` в переменных окружения Render).

## Возможности
- Создание, редактирование, сортировка, скрытие и удаление разделов.
- Типы блоков: `hero`, `content`, `cards`, `players`, `teams`, `matches`, `gallery`, `custom`.
- Текст, изображение, видимость и порядок для каждого раздела.
- Настройки названия сайта, логотипа, SEO-описания, цветов и подписей меню.
- Публичный API `GET /api/cms/content` возвращает настройки и разделы для отрисовки.
- Все операции редактирования требуют заголовок `X-Admin-Password`; публичное чтение CMS не требует авторизации.

## Изображения
В текущем редакторе файл до 1,5 МБ читается браузером как data URL. Выберите нужный раздел во вкладке «Изображения» и нажмите «Сохранить изображение в раздел» — редактор сохранит изображение в выбранный раздел автоматически. Для рабочего production-сайта предпочтительно подключить объектное хранилище (S3-compatible/Cloudinary) и хранить в PostgreSQL только URL: data URL раздувает размер записей и резервных копий.

## Важные ограничения первой версии
- Не все существующие блоки и элементы главной страницы имеют отдельные настройки CMS; пока подключены основные настройки, главный экран, пользовательские контентные блоки и часть видимости.
- Типы `players`, `teams` и `matches` описывают блоки, но не создают новую бизнес-логику. Новые программные функции и новые типы данных по-прежнему требуют кода.
- Нет отдельной системы черновиков/публикации, версионирования и отката изменений.
- Нет автоматического резервного копирования медиа.
- До выкладки требуется проверить Python-компиляцию, миграцию PostgreSQL и SQLite, доступ администратора/неавторизованного клиента, мобильную верстку и сохранение/отображение после перезагрузки.

## Проверочный сценарий
1. Войти в `/admin/cms` с `ADMIN_PASSWORD`.
2. Создать раздел с уникальным slug латиницей и дефисами.
3. Изменить заголовок, текст, порядок и видимость; сохранить.
4. Обновить главную страницу и убедиться, что публичный блок отображается/скрывается.
5. Во вкладке «Изображения» выбрать раздел, загрузить файл не больше 1,5 МБ, проверить предпросмотр и сохранить изображение в раздел.
6. Проверить настройки цвета, названия, SEO и меню.
7. Открыть API `/api/cms/content` и проверить, что секретов в ответе нет.
8. Повторить на мобильном экране и после перезагрузки сервиса.
