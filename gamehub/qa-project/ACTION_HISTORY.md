# GameHub - история работы

**Сайт:** https://gamehub-055p.onrender.com  
**Исходный код:** `gamehub/` в ветке `master`.

## API и база данных

- Раньше сообщалось, что `/api/players`, `/api/teams` и `/api/matches` возвращали `Not Found`.
- В историческом логе SQLite была ошибка `no such table: players`.
- Пользователь позже сообщил, что API работает на опубликованном стенде. Свежие HTTP-ответы не сохранены.
- В текущем `master` `gamehub/app.py` использует SQLite и вызывает `init_db()` при импорте и старте приложения.
- Скриншоты Render с PostgreSQL относятся к историческому деплою ветки `feature/postgres-persistence`; они не доказывают, что эта конфигурация соответствует текущему `master`.

## Каталог игроков

- Раньше игроки и статистика не отображались.
- В Console была ошибка `$(...).forEach is not a function`.
- В `gamehub/static/app.js` одиночный селектор заменили на `$$("[data-go]")`, возвращающий коллекцию элементов.
- Пользователь подтвердил, что каталог снова отображается. На скриншоте видны 64 игрока, 6 команд, 5 матчей и результат поиска `abc`.
- Полный ретест и регрессия после исправления не оформлены.

## Service Worker

Раньше наблюдалась ошибка `Response body is already used`. В текущем `gamehub/static/sw.js` обработчик fetch клонирует успешный ответ перед записью в cache. Это чтение кода, а не подтверждение выполнения в браузере. Повторный тест на актуальном стенде не подтверждён.

## Что проверить дальше

- Выполнить `pytest -q` в папке `gamehub` и сохранить реальный результат.
- Сверить ветку и commit опубликованного стенда с `master`.
- Проверить API, поиск, фильтры, создание и сохранение профиля.
- Проверить Service Worker, адаптивность, LFG и админку.

- Уточнены ожидаемые ответы для LFG, фильтрация матчей через API и различие между возможностями API и формами сайта.

- Результат свежего прогона тестов в эту запись не включён: документация обновлена, но это не является запуском автотестов.

## Проверка изоляции API-тестов и статуса регистрации — 17.10.2026

- В тестах обнаружено, что импорт `gamehub/app.py` выполняет `init_db()` сразу. Без отдельной настройки это могло создать файл базы в рабочей копии репозитория.
- Для импорта в тестах задан временный путь вне репозитория; тестовые функции по-прежнему создают и удаляют собственную тестовую базу.
- Проверено расхождение контракта регистрации: маршрут декларировал HTTP 201, но возвращал готовый `JSONResponse` со стандартным HTTP 200. Ответ регистрации исправлен на HTTP 201.
- Проверки регистрации в API-тестах приведены к ожидаемому HTTP 201.
- Автотесты после этих изменений пока не запускались/не подтверждены CI; статус проверки не отмечается как пройденный.
