# Баг-репорты GameHub

Этот журнал содержит подтверждённое наблюдение из предоставленного скриншота DevTools и шаблоны для дальнейших дефектов. Статус не меняется на Fixed/Verified без проверки исправления.

## GH-BUG-001 — Ошибка JavaScript при работе с кэшем Service Worker

- **Статус:** Open — требуется воспроизведение на текущем деплое.
- **Приоритет:** P1 (предварительно; уточнить после оценки влияния).
- **Серьёзность:** Major (предварительно).
- **Компонент:** PWA / service worker / кэширование frontend.
- **Окружение:** Chrome desktop; GameHub на Render; точная версия commit на скриншоте не зафиксирована.
- **Предусловия:** сайт открыт; DevTools Console доступна.
- **Шаги воспроизведения:**
  1. Открыть GameHub.
  2. Открыть DevTools → Console.
  3. Перезагрузить страницу и выполнить навигацию/запрос, вызывающий обновление ресурсов.
  4. Проверить консоль.
- **Фактический результат:** на приложенном пользователем скриншоте отображается ошибка: `Uncaught (in promise) TypeError: Failed to execute 'clone' on 'Response': Response body is already used`, ссылка на `sw.js` (строка около 20).
- **Ожидаемый результат:** Service Worker кэширует ресурсы без необработанных ошибок; обновление frontend работает предсказуемо.
- **Влияние:** возможны проблемы с обновлением/кэшированием frontend. Фактическое влияние на пользователя нужно подтвердить повторным тестом.
- **Доказательство:** скриншот DevTools, предоставленный пользователем в переписке 13.10.2026.
- **Рекомендации по диагностике:** проверить повторное использование объекта Response, порядок чтения body и вызова clone(), очистить/обновить регистрацию Service Worker на тестовом браузере и повторить тест после исправления.
- **Retest:** Not Run.
- **Regression:** Not Run.

## GH-BUG-002 — GET /api/players возвращал HTTP 500 из-за отсутствующей таблицы

- **Статус:** Historical observation — текущее состояние не подтверждено.
- **Приоритет:** P1.
- **Компонент:** API / SQLite initialization.
- **Фактический результат:** на предоставленном пользователем логе было `sqlite3.OperationalError: no such table: players` при GET `/api/players`; health endpoint при этом возвращал 200.
- **Ожидаемый результат:** схема БД создаётся до обработки API-запросов; GET `/api/players` возвращает 200 и список.
- **Влияние:** каталог игроков не загружался, хотя health-check был успешным.
- **Статус исправления:** после последующих изменений в коде схема создаётся при старте, однако отдельный retest не зафиксирован. Не считать дефект подтверждённо закрытым до проверки текущего стенда.
