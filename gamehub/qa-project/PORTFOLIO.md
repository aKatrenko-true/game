# Моё QA-портфолио: GameHub

## Обо мне

Я начинающий QA Engineer. Развиваю навыки функционального и API-тестирования веб-приложений, анализа причин дефектов, работы с тестовой документацией и проверки данных. В работе использую ИИ как помощника для анализа и подготовки артефактов, но проверяю выводы по исходному коду, контрактам API и фактическим результатам. Не отмечаю тест пройденным без подтверждения.

## Проект

**GameHub** - учебное веб-приложение с каталогом игроков, командами, матчами и REST API.

- **Репозиторий приложения:** https://github.com/aKatrenko-true/game
- **QA-документация:** [папка qa-project](README.md)
- **Демо-стенд:** https://gamehub-055p.onrender.com
- **Swagger / OpenAPI:** https://gamehub-055p.onrender.com/docs
- **Статус QA:** В работе - тестирование ведётся, полный регрессионный прогон ещё не подтверждён.

## Технологический стек

- **Frontend:** HTML, CSS, JavaScript (Vanilla JS; React в текущем проекте не используется).
- **Backend:** Python, FastAPI.
- **Хранение данных:** PostgreSQL в опубликованном окружении; SQLite поддерживается для локального режима.
- **Инструменты и подходы:** Chrome DevTools (Console, Network), Swagger/OpenAPI, GitHub, SQL для проверки данных, pytest - для запуска имеющегося набора тестов после подготовки окружения.

## Что я делаю в проекте

- Изучаю структуру приложения, исходный код, доступные API-маршруты и документацию.
- Составляю стратегию тестирования и тест-кейсы с предусловиями, шагами и проверяемыми ожидаемыми результатами.
- Планирую позитивные, негативные и регрессионные проверки.
- Проверяю REST API: методы, коды ответов, структуру данных и обработку ошибок в рамках доступного контракта.
- Диагностирую проблемы интерфейса через DevTools и сопоставляю ошибки JavaScript с поведением приложения.
- Документирую дефекты, сохраняю историю изменений и связываю тесты с проверяемыми областями.
- Отслеживаю статус каждого сценария и отделяю подтверждённые результаты от непроверенных.

## Пример работы с дефектом

**Проблема:** каталог игроков отображал сообщение «Игроки не найдены», а статистика не показывалась.

**Диагностика:** в Console наблюдалась ошибка `Uncaught TypeError: $(...).forEach is not a function`. В коде одиночный DOM-селектор использовался как коллекция элементов.

**Исправление:** селектор заменён на `$$("[data-go]")`, который возвращает коллекцию элементов.

**Результат:** пользователь подтвердил, что игроки снова отображаются. Это подтверждение результата исправления, а не заявление о полном независимом регрессионном прогоне.

## Текущие подтверждённые результаты и ограничения

- Пользователь подтвердил, что каталог игроков отображается после исправления JavaScript-селектора.
- Пользователь подтвердил, что новые записи сохраняются.
- В документации сохранено историческое наблюдение об ошибке Service Worker; актуальный статус требует повторной проверки.
- Полный регрессионный прогон разделов администрирования и LFG, адаптивности, доступности и безопасности не подтверждён.
- Наличие тест-кейса или команды запуска не означает, что тест был выполнен. Перед публикацией отчёта о прогоне необходимо выполнить проверки и записать реальные статусы Pass / Fail / Blocked / Не запускался.

## Что планирую проверить дальше

1. Выполнить актуальный smoke-набор: главная страница и ключевые API-маршруты.
2. Повторно проверить исправление каталога, поиск и фильтры.
3. Проверить создание записи и её сохранение после обновления страницы.
4. Повторно исследовать Service Worker и ошибки в Console.
5. Выполнить регрессию команд и матчей, затем проверить адаптивность и сценарии доступа.
6. Запустить имеющиеся автоматические тесты в корректно настроенном окружении и сохранить фактический отчёт.
