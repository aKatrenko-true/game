# GameHub — QA-проект

Документация тестирования GameHub: тест-кейсы, баг-репорты, результаты ручных проверок и доказательства. Проект ведётся отдельно от кода приложения.

## Сведения о проекте

- **Приложение:** GameHub — поиск игроков, команды, матчи и LFG.
- **Тестовый стенд:** https://gamehub-055p.onrender.com
- **Репозиторий:** https://github.com/aKatrenko-true/game
- **Рабочая ветка изменений:** `feature/postgres-persistence`
- **Основные технологии:** FastAPI, JavaScript, HTML/CSS, PostgreSQL на Render; SQLite поддерживается для локального запуска.
- **Дата актуализации документации:** 2026-10-13.
- **Общий статус QA:** In progress. Отдельные сценарии подтверждены пользователем; полный набор тестов не запускался/не подтверждён.

## Как читать статусы

- **Confirmed by user** — пользователь сообщил, что проверка прошла; это не независимый запуск со стороны QA.
- **Observed** — проблема видна на предоставленном скриншоте или описана пользователем.
- **Fixed, retest confirmed by user** — пользователь подтвердил работу после исправления.
- **Historical / retest required** — проблема была раньше, текущий статус не установлен.
- **Not Run** — проверка запланирована, но результат не получен.
- **Blocked** — выполнить проверку не удалось из-за внешней зависимости.

Не отмечать Pass только на основании успешного деплоя или health-check. Не заявлять, что скриншот или тест существует, если ссылка/файл не проверены.

## Рабочий процесс

1. Зафиксировать изменение и текущий commit/ветку.
2. Выполнить smoke-тесты API и главной страницы.
3. Проверить Network и Console при сбое интерфейса.
4. Создать баг-репорт с фактическим результатом, ожидаемым результатом и доказательством.
5. После исправления повторить исходный сценарий (retest).
6. Выполнить регрессию затронутых областей.
7. Записать результат, дату, окружение и доступные доказательства.

## Локальный запуск тестов API

Из каталога `gamehub`:

```bash
python -m pip install -r requirements.txt
pytest -q
```

Swagger UI локально: `http://127.0.0.1:8000/docs`.

## Правила безопасности

- Не добавлять пароли, токены, cookies, реальные персональные данные и открытые секреты Render.
- Для публичного портфолио использовать демонстрационные данные.
- Скриншоты до исправления помечать как **before fix**, после — **after fix**.
- Для каждой проверки указывать, что именно подтверждено, а что осталось непроверенным.
