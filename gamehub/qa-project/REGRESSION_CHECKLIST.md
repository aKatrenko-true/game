# Чек-лист регрессии GameHub

Отмечай пункт только после фактической проверки. Незапущенные сценарии оставляй пустыми. В отчёте указывай дату, окружение и commit.

## A. Smoke и API
- [ ] Главная открывается.
- [ ] `/api/health` возвращает HTTP 200 и JSON со статусом `ok`.
- [ ] `/api/players`, `/api/teams`, `/api/matches` возвращают JSON без 404/500.
- [ ] Результаты сохранены с HTTP-кодами и ссылкой на commit/CI, если проверка автоматическая.

## B. Каталог игроков
- [ ] Счётчики и популярные записи отображаются.
- [ ] В Console нет ошибки `$(...).forEach is not a function`.
- [ ] Поиск по полному и частичному никнейму работает.
- [ ] Фильтр игры работает отдельно и сбрасывается через «Все игры».
- [ ] Карточки CS2, WarDogs, Valorant и Apex Legends открывают каталог с выбранной игрой.
- [ ] Сверены материалы до и после исправления в [реестре скриншотов](screenshots/README.md).

## C. Создание и сохранение
- [ ] Создать уникальный тестовый профиль.
- [ ] Убедиться, что API возвращает HTTP 201 и профиль появляется в каталоге.
- [ ] После обновления страницы запись остаётся.
- [ ] Поведение после перезапуска процесса и после пересоздания окружения проверено отдельно.
- [ ] Не создавать дубликаты в общем стенде без необходимости; проверку HTTP 409 выполнять в изолированной тестовой базе.

## D. Команды и матчи
- [ ] Команды и матчи загружаются через API и отображаются на сайте.
- [ ] Фильтр матчей проверен через параметры API `status` и `game`.
- [ ] Создание команды и матча через API проверяется отдельно от интерфейса: наличие API-маршрута не означает, что форма создания реализована на сайте.
- [ ] Ошибка одного endpoint не оставляет страницу в бесконечной загрузке.

## E. База данных и деплой
- [ ] В текущем `master` подтверждено использование SQLite; путь к файлу зависит от `GAMEHUB_DB`.
- [ ] Отдельно зафиксированы фактические branch и commit опубликованного стенда.
- [ ] Если стенд использует другую СУБД или конфигурацию, это подтверждено актуальным кодом и настройками, а не историческим скриншотом.
- [ ] Проверены необходимые переменные окружения; значения секретов не копируются в отчёт.
- [ ] Данные проверены через API после обновления страницы и согласованного перезапуска.

## F. PWA
- [ ] После hard reload нет ошибки `Response body is already used`.
- [ ] Service Worker регистрируется без необработанных ошибок.
- [ ] После деплоя загружается актуальная версия frontend.
- [ ] Offline-поведение проверено фактически; неподтверждённые возможности не описываются как готовые.

## G. Адаптивность и клавиатура
- [ ] Проверены ширины 360, 390, 768, 1024 и 1440 px.
- [ ] Нет критического горизонтального переполнения.
- [ ] Фокус виден, основные действия доступны с клавиатуры.
- [ ] Скриншоты и результаты сохранены только после фактического прогона.

## H. Админка и LFG
- [ ] Без `X-Admin-Password` защищённый admin API возвращает HTTP 401, если `ADMIN_PASSWORD` настроен.
- [ ] При ненастроенном `ADMIN_PASSWORD` admin API возвращает HTTP 503.
- [ ] Неверный пароль даёт HTTP 401, корректный — успешный ответ.
- [ ] LFG проверен: список, фильтры, создание без авторизации (401), создание с авторизацией, валидация и запрет закрытия чужого объявления (403).
- [ ] Не считать доступ к странице `/admin` доказательством авторизации API.
