## 9. Политика тестового прогона

- Каждый кейс имеет стабильный ID; повторный запуск фиксируется отдельно с датой, commit и окружением.
- Для проверки загрузки медиа использовать только тестовые файлы, не пользовательские данные.
- Не записывать пароль, cookie, токен или значение `DATABASE_URL` в доказательства.
- Если сценарий нельзя выполнить из-за отсутствия доступа/стенда — Blocked с причиной, а не Pass.
- CI-тесты приложения и ручные кейсы стенда учитываются раздельно.
