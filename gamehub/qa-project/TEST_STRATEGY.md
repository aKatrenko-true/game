# Стратегия тестирования GameHub

## Контекст по коду

- Backend: Python и FastAPI (`gamehub/app.py`).
- База данных в текущем `master`: SQLite (`sqlite3`, файл задаётся через `GAMEHUB_DB`).
- Frontend: HTML, CSS и JavaScript в `gamehub/static/`.
- API-тесты: pytest и FastAPI TestClient в `gamehub/tests/test_api.py`.
- CI: GitHub Actions запускает `python -m pytest -q` при изменениях в `gamehub/**` и вручную.
- В репозитории есть API для игроков, команд, матчей, авторизации и LFG. Текущие UI-возможности проверяются отдельно.

## Области тестирования

- **Smoke:** главная и health endpoint.
- **API:** коды ответов, JSON, поиск, фильтры, валидация, дубликаты и права доступа.
- **Frontend:** навигация, каталоги, поиск, фильтры, формы и ошибки Console.
- **Данные:** создание записей и сохранение после обновления.
- **PWA:** Service Worker, cache и обновление ресурсов.
- **Дополнительно:** LFG, админка, адаптивность и клавиатурная навигация.

## Окружение

- Сайт: https://gamehub-055p.onrender.com
- API-документация стенда: https://gamehub-055p.onrender.com/docs
- Перед тестированием сверить URL, ветку и commit опубликованной версии. Скриншот с Render на ветке `feature/postgres-persistence` - историческое доказательство, а не подтверждение текущей конфигурации `master`.
- Для UI-диагностики подходят Chrome DevTools: Console, Network и Application.

## Приоритеты

- **P0** - недоступность сайта, потеря данных или критическая проблема с доступом.
- **P1** - не работает основной сценарий, API или сохранение.
- **P2** - заметная ошибка с обходным путём.
- **P3** - косметическая проблема.

Приоритет предварительный, если влияние ещё не проверено.

## Правила выполнения

Записывать дату, commit, окружение, фактический результат и доказательства. После исправления повторять проблемный сценарий и затронутую регрессию. Незапущенные проверки не отмечать как пройденные.

## Тестовые данные и безопасность

Использовать демонстрационные записи. На общем стенде не удалять чужие данные. Не публиковать пароли, токены, cookies и значения секретных переменных.

## Что ещё проверить

Полный регрессионный прогон, Service Worker, LFG, админку, адаптивность и безопасность.
