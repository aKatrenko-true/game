# Стратегия тестирования GameHub

## 1. Цель
Проверять пользовательские сценарии, REST API, сохранение данных, frontend, PWA и регрессию после изменений. Каждый дефект должен иметь шаги воспроизведения и доказательства.

## 2. Объект
- Frontend: HTML/CSS/JavaScript, навигация, каталоги, поиск, фильтры, формы.
- Backend: FastAPI REST API.
- База: PostgreSQL на Render; SQLite поддерживается для локального режима.
- PWA: Service Worker, кэш и обновление ресурсов.
- Дополнительные области: команды, матчи, LFG, личный кабинет и администрирование.

## 3. Окружение
- Стенд: https://gamehub-055p.onrender.com
- Ветка Render, подтверждённая скриншотом: `feature/postgres-persistence`.
- Commit `b13e037` — последний commit, который был виден на предоставленном скриншоте Render; последующие изменения нужно сверять в Render.
- Ручная диагностика: Chrome desktop, DevTools Console/Network/Application.
- API: Swagger UI, pytest/httpx; Postman — дополнительный инструмент.

## 4. Приоритеты
- P0/Critical — недоступность, потеря/утечка данных, обход авторизации.
- P1/High — сломан ключевой сценарий каталога, API или сохранения.
- P2/Medium — существенная ошибка с обходным путём.
- P3/Low — косметическая ошибка.
Приоритеты предварительные, если влияние не подтверждено.

## 5. Виды проверок
Smoke, функциональные, API, валидация, сохранение данных, регрессия, диагностика Console/Network, PWA, responsive (360/390/768/1024/1440 px), базовая безопасность и клавиатурная доступность.

## 6. Тестовые данные и безопасность
Использовать демонстрационные записи и уникальные никнеймы. Не удалять существующие данные на общем стенде. Не сохранять в отчётах пароли, токены, cookies или значения секретных переменных. Скриншоты настроек проверять на отсутствие раскрытых секретов.

## 7. Критерии начала
Известны окружение и commit; стенд доступен; ожидаемый результат определён; данные безопасны.

## 8. Критерии завершения
Выполнены согласованные smoke/P1 кейсы; открытые дефекты указаны; исправления прошли retest; регрессия выполнена или помечена Not Run. Не объявлять Ready только по health-check.

## 9. Риски
- По предыдущему скриншоту бесплатная PostgreSQL база Render истекает 12 ноября 2026 г.; до этой даты нужно решить вопрос хранения данных.
- Free web service может засыпать.
- Service Worker может отдавать закэшированные ресурсы.
- Полный аудит безопасности, нагрузочное тестирование и WCAG-аудит не подтверждены.

## 10. Статусы и отчётность
Pass, Fail, Blocked, Not Run. Отдельно использовать «подтверждено пользователем», если результат сообщён пользователем, а не получен независимым запуском. Для каждого прогона фиксировать дату, commit, браузер, результат и ссылку на доказательство.
