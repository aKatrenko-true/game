# WARDOGS и AXIS в GameHub — требования и план реализации

**Статус:** базовая страница сообщества и переход в Discord реализованы в коде; браузерная проверка и деплой не подтверждены. Реальный мониторинг и система событий не реализованы.  
**Ветка:** `master`  
**Дата:** 19.10.2026  
**Связанные документы:** [тест-кейсы](WARDOGS_TEST_CASES.md), [общий план развития](FEATURE_BACKLOG.md).

## 1. Цель

Развить GameHub в полезный центр сообщества WARDOGS и AXIS: помочь игрокам находить состав, узнавать об активности, собираться на игровые события и возвращаться на сервер. Не подменять реальные игровые данные демонстрационными.

## 2. Текущий объём

- Добавлена отдельная вкладка **AXIS / WARDOGS** в навигации GameHub.
- На главной странице добавлен промоблок сообщества.
- Добавлена адаптивная страница сообщества с CTA в Discord, переходом к каталогу игроков WarDogs и блоками сообщества/сборов.
- Discord-приглашение, предоставленное пользователем: https://discord.gg/h4ut2NdET
- В карточке мониторинга явно указано, что источник данных не подключён; реальные показатели не выдумываются.
- В каталоге остаются демонстрационные игроки и команды WarDogs; они не подтверждают реальные аккаунты или статистику.
- Изменены `gamehub/static/index.html`, `gamehub/static/app.js`; добавлен `gamehub/static/axis.css`.
- Код записан в `master`; доступность обновления на опубликованном Render-стенде отдельно не подтверждена.

## 3. Что уже есть в GameHub

- Каталог игроков с фильтром по игре.
- Каталог команд и расписание матчей.
- LFG (поиск напарников/команды).
- FastAPI, REST API и SQLite в текущем коде `gamehub/app.py`.
- В интерфейсе карточка WARDOGS ведёт в каталог игроков с фильтром.

## 4. Следующие этапы

### Этап 1. Проверка страницы сообщества

- Проверить навигацию AXIS на desktop и mobile.
- Проверить открытие Discord-ссылки.
- Проверить переход в каталог с фильтром WarDogs.
- Проверить адаптивность на ширинах 320, 375, 768 и 1280 px.
- Провести smoke/regression существующих функций после обновления.

### Этап 2. Мониторинг сервера

После подтверждения источника данных:
- Установить, где размещён сервер AXIS и кто управляет им.
- Получить адрес/порт сервера или документированный API хостинга.
- Проверить доступные поля: доступность, онлайн, максимум игроков, карта, регион и время последней проверки.
- Добавить периодическую проверку, тайм-ауты, историю и журналирование без секретов.
- При ошибке источника показывать «Нет данных» и время последней успешной проверки, не подменять ошибку нулевым онлайном.

### Этап 3. Механика «Собираем AXIS»

- Создание события с датой/временем и описанием.
- Регистрация и отмена участия с защитой от дубликатов и изменения чужих регистраций.
- Показ количества записавшихся и цели, если она задана организатором.
- Напоминания только после реализации явного согласия на уведомления.
- Пока даты сборов не предоставлены, интерфейс направляет пользователя в Discord за актуальным расписанием и не показывает выдуманные события.

### Этап 4. Аналитика и дальнейшие возможности

- Аналитика переходов на Discord и к поиску игроков.
- Каталог оружия, техники и сборок — после подтверждения актуальности данных и источника.
- Публичный рейтинг — только при наличии достоверных данных и понятных правил подсчёта.

## 5. Функциональные требования MVP

| ID | Требование | Критерий приёмки |
|---|---|---|
| AXIS-F-01 | Игрок открывает страницу WARDOGS/AXIS | Страница загружается и содержит понятные разделы |
| AXIS-F-02 | Игрок переходит к поиску команды | Открывается каталог с фильтром WarDogs |
| AXIS-F-03 | Игрок видит состояние сервера | Источник и время проверки доступны; неподтверждённые данные не показываются как реальные |
| AXIS-F-04 | Игрок узнаёт о ближайшем сборе | Отображается проверенное расписание либо честное сообщение, что оно пока не опубликовано на GameHub |
| AXIS-F-05 | Игрок регистрируется на сбор | Повторная регистрация не создаёт дубликат |
| AXIS-F-06 | Игрок отменяет участие | Отменить участие может только сам участник либо уполномоченный организатор |
| AXIS-F-07 | Источник мониторинга не отвечает | Интерфейс показывает «Нет данных»/ошибку, а не ложный статус |
| AXIS-F-08 | Страница открывается на мобильном устройстве | Нет горизонтального переполнения на целевых ширинах; основные действия доступны |
| AXIS-F-09 | Игрок открывает Discord | Открывается приглашение https://discord.gg/h4ut2NdET в новой вкладке |

## 6. Нефункциональные требования

- Не выводить секреты, токены и приватные данные в клиентский код, логи или документацию.
- Валидировать все входные данные на сервере.
- Для мониторинга предусмотреть тайм-ауты и ограничение частоты запросов.
- Не считать демоданные реальной статистикой игроков.
- Сохранять существующие сценарии GameHub; после изменений запускать регрессионные проверки.
- Любой результат теста отмечать как Pass/Fail/Blocked только после фактического выполнения; к баг-репортам прикладывать реальные доказательства.
