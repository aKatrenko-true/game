# WARDOGS и AXIS в GameHub — требования и план реализации

**Статус:** требования подготовлены; техническая реализация не начата.  
**Ветка:** `master`  
**Дата:** 18.10.2026  
**Связанные документы:** [тест-кейсы](WARDOGS_TEST_CASES.md), [общий план развития](FEATURE_BACKLOG.md).

## 1. Цель

Развить GameHub в полезный центр сообщества WARDOGS и клана AXIS: помочь игрокам находить состав, узнавать об активности, собираться на игровые события и возвращаться на сервер. Не подменять реальные игровые данные демонстрационными.

## 2. Что уже есть в репозитории

- Каталог игроков с фильтром по игре.
- Каталог команд и расписание матчей.
- LFG (поиск напарников/команды).
- FastAPI, REST API и SQLite в текущем коде `gamehub/app.py`.
- В демоданных есть игроки и команды с игрой `WarDogs`; эти записи не являются подтверждением реальных аккаунтов или статистики.
- В интерфейсе карточка WARDOGS ведёт в каталог игроков с фильтром. Отдельной страницы мониторинга игрового сервера в просмотренных файлах не обнаружено.

## 3. Ценность для пользователя

1. Быстро найти игроков WARDOGS и договориться об игре.
2. Узнать о ближайшем сборе AXIS.
3. Открыть страницу клана с понятной информацией и инструкцией подключения.
4. Посмотреть статус и онлайн игрового сервера, если доступен надёжный источник этих данных.
5. Возвращаться к событиям и обновлениям сообщества.

## 4. План по этапам

### Этап 0. Подтверждение источников и границ интеграции

- Установить, где размещён сервер AXIS и кто управляет им.
- Получить адрес/порт игрового сервера или документированный API хостинга.
- Проверить, какие данные можно получить стабильным способом: доступность, онлайн, максимум игроков, карта, регион, время последней проверки.
- До подтверждения источника не показывать придуманный онлайн, пинг, карту или статус как реальные.

### Этап 1. Публичная страница WARDOGS / AXIS

- Информация об игре и клане.
- Инструкция подключения и проверенная ссылка на сообщество, если предоставлена владельцем.
- Список ближайших игровых сборов/событий.
- Каталог игроков WARDOGS и переход к LFG с выбранной игрой.
- Пустые состояния и явная маркировка данных, которые пока не подключены.
- Адаптивность мобильного экрана и доступность клавиатурной навигации.

### Этап 2. Мониторинг сервера

После подтверждения источника данных:
- Периодическая проверка доступности сервера.
- Хранение временных измерений и истории доступности.
- Отображение онлайна только при успешном получении актуальных данных.
- При ошибке источника показывать «Нет данных» и время последней успешной проверки, не подменять ошибку нулевым онлайном.
- Предусмотреть тайм-ауты, ограничение частоты запросов и журналирование ошибок без секретов.

### Этап 3. Механика «Собираем AXIS»

- Создание события с датой/временем и описанием.
- Регистрация участников на сбор.
- Показ количества записавшихся и целевого количества, если цель задана организатором.
- Напоминание участникам — только после реализации явного согласия на уведомления.
- После события — статус и результаты, если их вводит организатор или можно получить из подтверждённого источника.
- Защита от повторных регистраций, спама и изменения чужих событий.

### Этап 4. Аналитика и дальнейшие возможности

- Посещения страницы, переходы к инструкции подключения и регистрации на события.
- Источники переходов через разрешённые UTM-метки.
- Каталог оружия, техники и сборок — после подтверждения актуальности данных и источника.
- Публичный рейтинг — только при наличии достоверных данных и понятных правил подсчёта.

## 5. Функциональные требования MVP

| ID | Требование | Критерий приёмки |
|---|---|---|
| AXIS-F-01 | Игрок открывает страницу WARDOGS/AXIS | Страница загружается и содержит понятные разделы |
| AXIS-F-02 | Игрок переходит к поиску команды | Открывается каталог с фильтром WarDogs |
| AXIS-F-03 | Игрок видит состояние сервера | Данные имеют источник и время проверки; неподтверждённые данные не показываются как реальные |
| AXIS-F-04 | Игрок видит ближайший сбор | Отображаются дата, время, описание и статус события |
| AXIS-F-05 | Игрок регистрируется на сбор | Повторная регистрация не создаёт дубликат |
| AXIS-F-06 | Игрок отменяет участие | Отменить участие может только сам участник либо уполномоченный организатор |
| AXIS-F-07 | Сервер мониторинга не отвечает | Интерфейс показывает «Нет данных»/ошибку, а не ложный статус |
| AXIS-F-08 | Страница открывается на мобильном устройстве | Нет горизонтальной прокрутки на целевых ширинах; основные действия доступны |

## 6. Нефункциональные требования

- Не выводить секреты, токены и приватные данные в клиентский код, логи или документацию.
- Валидировать все входные данные на сервере.
- Для мониторинга предусмотреть тайм-ауты и ограничение частоты запросов.
- Не считать демоданные реальной статистикой игроков.
- Сохранять существующие сценарии GameHub; после изменений запускать регрессионные проверки.
- Любой результат теста отмечать как Pass/Fail/Blocked только после фактического выполнения; к баг-репортам прикладывать реальные скриншоты.

## 7. Вопросы, блокирующие реальный мониторинг

1. Где размещён сервер AXIS: собственный/арендованный сервер или игровой хостинг?
2. Какой адрес и порт сервера, если их можно публиковать?
3. Есть ли API/панель хостинга с данными об онлайне?
4. Какие ссылки можно размещать на странице клана (Discord/Steam/другое)?
5. Нужно ли игрокам регистрироваться на игровые сборы через GameHub или пока достаточно расписания?

Пока эти данные не подтверждены, мониторинг и уведомления остаются запланированными, а не реализованными.
